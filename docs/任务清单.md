# GitHub Issue 与验收清单

每个条目对应一个 GitHub Issue。负责人完成实现后，在 PR 中填写验证命令和结果，由另一名成员审查。

## Issue 1：文献、网络模型与固定拓扑

负责人：成员 A  
依赖：无  
交付：

- [ ] 维护不少于 6 篇论文的题名、作者、年份、出处、DOI/链接和与本项目的关系。
- [ ] 选择至少 2 篇直接相关论文，分析网络模型、路由规则、实验参数和可复现边界。
- [ ] 实现 36 节点固定拓扑，包含节点编号、轨道/面内编号、双向链路、传播时延和容量。
- [ ] 数据字段和单位写入文档。
- [ ] 对比本模型与真实 Walker 星座或真实星历的差异。
- [ ] 添加拓扑单元测试。

验收：同一种子生成完全相同的邻接表；每个节点连接数的设计规则可解释；无孤立节点。

## Issue 2：均匀/热点业务与有限队列

负责人：成员 B  
依赖：Issue 1  
交付：

- [ ] 实现均匀业务和热点业务生成器。
- [ ] 支持分组大小、发送速率、仿真时长和固定随机种子。
- [ ] 实现有限 FIFO 队列、发送占用、排队和队列满丢弃。
- [ ] 输出每个分组的时间戳、路径和最终状态。
- [ ] 提供至少一份可提交的小型基础数据及字段说明。
- [ ] 添加业务可复现性和队列边界单元测试。

验收：相同种子得到相同业务；发送数 = 交付数 + 排队/无路由丢弃数 + 仿真结束时仍在途数。

## Issue 3：传播时延 Dijkstra

负责人：成员 C  
依赖：Issue 1、Issue 2  
交付：

- [ ] 实现基于传播时延的最短路径。
- [ ] 支持固定链路代价和明确的重算周期。
- [ ] 定义无可用路径、链路不可用和队列满时的处理策略。
- [ ] 与 NetworkX 或独立手算小图对照。
- [ ] 添加单元测试。

验收：小图中的路径和代价可手算验证；所有返回路径的边均存在且方向合法。

## Issue 4：队列加权与简化交通灯路由

负责人：成员 D  
依赖：Issue 1、Issue 2、Issue 3  
交付：

- [ ] 实现传播时延 + 队列状态的加权路径。
- [ ] 说明代价公式、单位、队列读取时刻与更新周期。
- [ ] 实现简化交通灯/下一跳队列状态路由。
- [ ] 写明 TLR 文献中的保留机制、简化部分和代码来源。
- [ ] 对接 Dijkstra 基线并验证三者使用相同输入。
- [ ] 添加边界和拥塞场景测试。

验收：拥塞时路由能够响应队列变化；无路由时不会崩溃或静默丢包；配置中的所有阈值均有文档。

## Issue 5：统一实验、统计与绘图

负责人：成员 E  
依赖：Issue 2 至 Issue 4  
交付：

- [ ] 读取 `configs/base.yaml`，遍历 3 档负载、2 类业务、5 个种子。
- [ ] 每次运行记录参数摘要、种子、代码提交号和结果。
- [ ] 统计均值、标准差/置信区间、P95 时延、交付率、吞吐量和链路利用率。
- [ ] 生成时延、交付率、吞吐量随负载变化图，以及链路负载分布图。
- [ ] 提供一条命令可运行的基础实验脚本。
- [ ] 检查所有算法和种子的组合是否完整。

验收：从干净环境执行基础脚本可重现图表；汇总表每个负载/业务组合都有 3 种算法和 5 个种子。

## Issue 6：集成测试、报告与答辩材料

负责人：成员 F  
依赖：Issue 5  
交付：

- [ ] 全量运行测试和基础实验，修复集成问题。
- [ ] 完成不少于 3000 字报告。
- [ ] 报告包含文献、模型假设、算法原理、实现、结果、波动、局限、分工和 AI 使用核验。
- [ ] 核验所有图表与最终代码版本一致。
- [ ] 完善 README、运行说明、数据说明和引用清单。
- [ ] 按课程要求准备 PPT，并从零开始完整彩排一次。

验收：另一成员按 README 在新环境完成安装和基础实验；报告中的数字可由仓库脚本生成。

## 可选任务

- 算法改进：调整拥塞门限或增加备用下一跳，并做消融实验。
- 参数敏感性：至少研究队列容量、热点位置或拥塞门限中的两项。

选做任务必须创建独立 Issue 和分支，不得直接混入必做任务的 PR。
