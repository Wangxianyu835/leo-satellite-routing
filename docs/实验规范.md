# 统一实验规范

## 公共实验条件

基础实验使用 `configs/base.yaml`。所有算法必须使用同一拓扑、链路时延、链路容量、队列容量、业务流、随机种子和仿真时长。比较算法时不得单独调整输入。

初始参数：

- 拓扑：6 个轨道面，每面 6 颗卫星，共 36 个节点。
- 连接：同轨道相邻卫星、相邻轨道对应卫星之间建立双向链路。
- 负载档位：每个源节点 1、3、6 Mbit/s，形成至少 3 档网络负载。
- 业务：均匀业务，以及随机选择热点区域后的热点业务。
- 独立实验：每档负载和业务类型使用 5 个固定种子。
- 指标：平均端到端时延、分组交付率、有效吞吐量、链路负载分布。

链路时延、容量、分组大小和队列长度保存为配置字段。报告中使用毫秒、Mbit/s、bit、packet 和百分比，并在首次出现时说明换算。

## 路由代价

传播时延最短路径的链路代价为传播时延，单位毫秒。

队列加权路径建议使用如下形式，具体实现和参数必须在报告中明确：

```text
cost(e) = propagation_delay_ms(e) + queue_term(e)
queue_term(e) = queue_weight * queue_occupancy_at_tx(e) * packet_size_bit / link_capacity_bps * 1000
```

`queue_term` 应换算为毫秒。队列权重、路径重算周期和拥塞门限必须写入配置，比较时保持相同。

## 仿真边界

- 使用固定拓扑，不计算真实星历和地球自转。
- 链路传播时延使用预设常数，不代表某个真实星座的逐时刻几何距离。
- 链路容量、队列长度和业务模型均为简化值。
- 报告必须说明这些假设对结果外推的限制。

## 路由失败和拥塞

每组实验必须预先定义并记录：

- 下一跳队列已满时，是等待、绕行还是丢弃。
- 所有候选路径都不可用时的处理方式。
- 分组是否允许拆包。
- 时延是否包含发送、排队、传播和处理时延。
- 链路代价在实验过程中多久更新一次。

## 结果文件要求

原始结果至少包含以下字段：

```text
run_id, algorithm, traffic_type, offered_load_mbps, seed,
packet_size_bit, duration_ms, generated_packets, delivered_packets,
dropped_packets, mean_e2e_delay_ms, p95_e2e_delay_ms,
delivery_ratio, throughput_mbps, config_hash, git_commit
```

链路统计至少包含：

```text
run_id, link_id, capacity_mbps, transmitted_packets,
transmitted_bits, utilization_ratio, queue_drop_packets
```

程序生成的大型结果默认写入 `results/`，不提交到 Git。用于复现的最小基础数据写入 `data/`，单个文件建议小于 5 MB。

## 图表与核验

- 时延、交付率和吞吐量使用负载为横轴，并显示 5 个种子的均值与误差条。
- 链路负载分布使用直方图或 CDF，横轴为利用率，纵轴说明为链路数量或比例。
- 每次汇总前检查所有算法是否完整覆盖所有种子；缺一个种子就不能计算正式均值。
- 报告中的表格和图片必须由固定脚本重新生成。
